# Smart Water backend (ASP.NET Core, .NET 10)

One app that runs everything on the server side:

| Folder | What it does |
|---|---|
| `Mqtt/` | The connection to the broker (EMQX). Subscribes to every node's `readings`, `status` and `ack` and hands each message on. `ContractMessages.cs` mirrors `docs/mqtt-contract.md` |
| `Ingestion/` | Checks each readings message, converts pulses to L/min and millivolts to kPa with the calibration in the `sensors` table, stores it, and puts bad data in `rejected_readings` |
| `Nodes/` | Online / offline: the last will, or 30 s with no message. Raises and clears `node_offline` alerts |
| `Detection/` | Per-zone mass balance: residual = inlet - outlet - baseline offset. Suspected, then confirmed after 10 s, then resolved after 10 s below the threshold |
| `Alerts/` | Leak, offline and valve-failure alerts; acknowledge and resolve |
| `Valves/` | Valve commands: node online? interlock (or `force` once the operator confirms the pump is off)? Then publish, wait for the ack, time out after 5 s |
| `Auth/` | Login against BCrypt hashes, lockout after 5 wrong passwords for 15 min, JWT tokens |
| `Api/` | The HTTP endpoints the web app uses (`web/src/data/api/apiSource.ts`), plus calibration |
| `Live/` | The SignalR hub `/hubs/live` that pushes readings and changes to the browsers |
| `Rig/` | The rig configuration and settings, cached in memory |

It also serves the built web app (from `wwwroot` on Render, from `../../../web/dist` locally)
and answers `GET /api/health` with the database and MQTT status.

## Run locally

```powershell
cd ..\web; npm run build; cd ..\backend\src\SmartWater.Api
dotnet run        # http://localhost:5000
```

Then run the simulator (`tools\simulator`, `dotnet run`) and log in. Logins are created with
`tools\dbsetup` (see its README); there are no default users.

## Configuration

| Setting | Locally | On Render |
|---|---|---|
| Neon connection string | `DATABASE_URL` in `.env.local` at the repo root, written by `neon deploy` / `neon env pull` (Git ignores it) | Env var `DATABASE_URL` |
| MQTT broker | user-secrets `Mqtt:Host`, `Mqtt:Username`, `Mqtt:Password` (docs/setup.md §2) | `Mqtt__Host`, `Mqtt__Username`, `Mqtt__Password` |
| Token signing key | Random on every start (log in again after a restart) | `Jwt__Key`, generated by Render |
| Port | 5000 (launchSettings.json) | Render's `PORT` |

Without `Mqtt:Host` the app still runs, just without live data. For a local test broker:
`dotnet run -- --Mqtt:Host=localhost --Mqtt:Port=1883 --Mqtt:UseTls=false`.

## Calibration endpoints

| Endpoint | Who | What |
|---|---|---|
| `POST /api/zones/{id}/baseline` | administrator, technician | With every leak point shut and water flowing for a minute: records the zone's normal inlet - outlet mismatch over the last 60 s as its new baseline |
| `POST /api/sensors/{id}/zero` | administrator, technician | With the pump off: the pressure sensor's average voltage over the last 10 s becomes its zero |
